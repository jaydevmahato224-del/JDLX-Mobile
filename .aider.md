# JDLX-Mobile AI Project Guide

Version: 1.0

This file contains the permanent development rules for the JDLX-Mobile project.

Every AI session must follow these rules before making any changes.

==================================================
PROJECT IDENTITY
==================================================

Project Name:
JDLX-Mobile

Project Type:
Modern Ecommerce Platform

IMPORTANT

This project already has its own UI, UX, branding, architecture and coding style.

Never redesign this project.

Never convert it into another ecommerce design.

==================================================
PRIMARY GOAL
==================================================

Your primary responsibility is to improve the existing project.

Never replace existing systems without approval.

Always preserve project consistency.

==================================================
GOLDEN RULES
==================================================

Rule 1

Never modify business logic unless explicitly requested.

Rule 2

Never modify files that were not added to the current session.

Rule 3

Never redesign the existing UI.

Rule 4

Never change project theme.

Rule 5

Never rename folders or move files without approval.

Rule 6

Always explain the problem first.

Rule 7

Always explain the solution.

Rule 8

Wait for approval before editing.

Rule 9

Edit only requested files.

Rule 10

Keep responses short, technical and accurate.

==================================================
UI / UX RULES
==================================================

Preserve the current JDLX-Mobile design.

Never redesign pages.

Never change layout without permission.

Never replace colors.

Never replace typography.

Never replace spacing.

Never replace icons.

Never replace animations.

Never replace transitions.

Never change component hierarchy.

Preserve existing visual identity.

==================================================
THEME RULES
==================================================

The current theme is the official JDLX-Mobile theme.

Do not replace it.

Do not modernize it.

Do not convert it to:

- Blinkit
- Amazon
- Flipkart
- Zepto
- Meesho
- Any other ecommerce UI

Always preserve the existing project theme.

==================================================
BUSINESS LOGIC
==================================================

Business logic has highest priority.

Never change:

Authentication

Orders

Payments

Inventory

Warehouse

Admin permissions

Coupons

Pricing

Delivery logic

Taxes

Discount calculations

Product logic

Cart logic

Wishlist logic

unless explicitly instructed.

==================================================
MODULE BOUNDARIES
==================================================

Treat every module independently.

Frontend

Backend

Admin

Warehouse

Infrastructure

Never modify unrelated modules.
==================================================
CODING STANDARDS
==================================================

Always understand existing code before editing.

Never rewrite a working implementation.

Prefer fixing instead of replacing.

Keep edits small and focused.

Avoid unnecessary refactoring.

Do not introduce breaking changes.

Preserve coding style used in the file.

Follow existing folder structure.

==================================================
FILE SAFETY
==================================================

Before editing any file:

1. Read the complete file.
2. Understand dependencies.
3. Check imports.
4. Check exports.
5. Check API usage.
6. Check state management.
7. Then edit only what is required.

==================================================
API RULES
==================================================

Never break existing APIs.

Never rename API routes.

Never change request or response formats without approval.

Maintain backward compatibility.

==================================================
FRONTEND RULES
==================================================

Preserve existing UI.

Preserve existing animations.

Preserve responsive behaviour.

Do not remove loading states.

Do not remove error handling.

Do not remove accessibility.

==================================================
BACKEND RULES
==================================================

Keep endpoints stable.

Never remove validations.

Never remove authentication.

Never remove authorization.

Never remove logging.

Never remove error handling.

==================================================
DATABASE RULES
==================================================

Never delete tables.

Never rename columns.

Never remove migrations.

Never modify schema without approval.

==================================================
PERFORMANCE
==================================================

Avoid unnecessary re-renders.

Avoid duplicate API calls.

Reuse existing components whenever possible.

Prefer optimized solutions.

==================================================
WORKFLOW
==================================================

Always follow this order:

1. Analyze problem.
2. Explain findings.
3. Suggest solution.
4. Wait for approval.
5. Make changes.
6. Explain changes made.
7. Mention affected files.
==================================================
JDLX-MOBILE PROJECT SPECIFIC RULES
==================================================

This project already has a complete UI and UX.

Never redesign any page.

Never replace the existing visual identity.

Always preserve the current JDLX-Mobile experience.

==================================================
DESIGN PROTECTION
==================================================

Keep the current design exactly as it is.

Do not replace:

Layouts

Cards

Navigation

Buttons

Typography

Spacing

Colors

Animations

Icons

Glass effects

Responsive behavior

Only change UI when explicitly requested.

==================================================
SAFE DEVELOPMENT
==================================================

Before writing code:

Understand the feature.

Understand related files.

Understand dependencies.

Identify risks.

Then implement the smallest possible change.

==================================================
EDITING STRATEGY
==================================================

Always prefer:

Small commits.

Small edits.

Small pull requests.

Small code changes.

Avoid large rewrites.

==================================================
BUG FIX STRATEGY
==================================================

When fixing bugs:

Identify root cause.

Explain root cause.

Propose fix.

Implement minimal fix.

Verify nothing else is broken.

==================================================
CODE QUALITY
==================================================

Write clean code.

Avoid duplicated code.

Reuse existing utilities.

Reuse existing components.

Prefer readability over clever code.

==================================================
COMMUNICATION STYLE
==================================================

Always communicate in simple English.

Keep explanations short.

Mention affected files.

Mention possible risks.

Mention testing steps.

Never assume requirements.

Ask when uncertain.

==================================================
FINAL RULE
==================================================

The highest priority is preserving the stability,
business logic, design, and architecture of the
existing JDLX-Mobile project.

Never sacrifice stability for unnecessary improvements.
